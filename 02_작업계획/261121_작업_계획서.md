# 5일차 작업 계획서

- 날짜:2026-11-21

## 1. 목표

- 본사와 지사의 경로를 RIPv2로 바꿔 지사에 네트워크가 늘어도 본사와 저절로 연결될 수 있게 한다.
- 동적 라우팅이 잘못된 경로를 받아들이지 않게 한다.

## 2. 작업 대상

| 대상 | 무엇을 |
|------|--------|
| BR-R1, HQ-R1 | 주 정적 경로 삭제 / RIPv2 / passive-interface / 인증 |
| HQ-R1              | 예비 경로를 192.168.100.0 /24 |
| BR-R1 | 창고 네트워크 (루프백 1 / 192.168.20.32 /27) |

## 3. 작업 내용

1. 주 회선의 정적 라우팅 경로를 지운다. (예비 경로는 남긴다.)
2. 두 라우터에 RIPv2를 켠다.
3. 예비 회선을 passive 모드로 둔다.
4. 지사에 창고(물류센터 네트워크)를 만들어 동적 라우팅 되는지 확인한다.
5. 장애 실습 하고 예비 경로를 /24로 바꾼다.
6. 사무실 쪽 포트를 passive 모드로 두고 RIP이 켜진 포트에 모두 인증을 설정한다.

## 4. 확인 방법

| 확인할 것 | 방법 | 기대하는 결과 |
|-----------|------|---------------|
| 두 라우터가 이어졌다 | BR-R1에서 `ping 192.168.99.1`           | Reply                           |
| 지사에서 본사로 간다 | BR-PC1에서 `tracert 192.168.10.1`      | 세 칸                             |
| 경로가 들어갔다    | `show ip route static`                | 본사 S, 지사 S*                     |
| 예비 회선이 이어졌다 | HQ-R1에서 `ping 192.168.100.2`           | Reply                           |
| 장애 때 넘어간다   | 본사 Gi0/1 shutdown 중 BR-PC1의 `ping -t` | 몇 개 빠진 뒤 다시 Reply, 경로표에 [250/0] |

## 5. 되돌리는 방법

- 모듈을 꽂기 전에 반드시 저장한다. 꽂은 뒤 설정이 비면 저장한 설정으로 부팅된다
- 경로를 잘못 넣었으면 같은 줄 앞에 `no` 를 붙여 지운다
- 장애 시험 뒤에는 반드시 `no shutdown` 으로 주 회선을 살린다
