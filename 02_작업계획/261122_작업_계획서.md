# 6일차 작업 계획서

- 날짜:2026-11-22

## 1. 목표

- RIP의 회선 속도를 모르고 장애를 늦게 알아채는 문제를 OSPF로 풀수 있는지 실험한다.
- 실험은 OSPF 브랜치에서 진행하고, 비교한 후 병합한다.

## 2. 작업 대상

| 대상 | 무엇을 |
|------|--------|
| BR-R1, HQ-R1 | RIP와 예비 정적 경로 삭제 / 루프백 0 / OSPF / passive / MD5 인증 |
| BR-R1 | 창고 네트워크 (루프백 1 / 192.168.20.32 /27) |

## 3. 작업 내용

1. OSPF 브랜치를 만든다.
2. RIP와 예비 정적 경로를 지운다.
3. 루프백 0와 router-id 를 정한다.
4. area 0 하나로 OSPF 활성화 한다.
5. 이웃, 경로, 비용을 확인하고 장애 실험을 한다.
6. passive-interface default 로 사무실 쪽을 닫는다.
7. 이웃 구간 네 곳에 MD5 인증을 건다.
(먼저 HQ-R1에만 걸어서 이웃이 끊기는 것을 확인하고 BR-R1에 설정하여 이웃이 연결되는 것을 확인한다.)

## 4. 확인 방법

| 확인할 것 | 방법 | 기대하는 결과 |
|-----------|------|---------------|
| 두 라우터가 이어졌다 | BR-R1에서 `ping 192.168.99.1`           | Reply                           |
| 지사에서 본사로 간다 | BR-PC1에서 `tracert 192.168.10.1`      | 세 칸                             |
| 경로가 들어갔다    | `show ip route static`                | 본사 S, 지사 S*                     |
| 예비 회선이 이어졌다 | HQ-R1에서 `ping 192.168.100.2`           | Reply                           |
| 장애 때 넘어간다   | 본사 Gi0/1 shutdown 중 BR-PC1의 `ping -t` | 몇 개 빠진 뒤 다시 Reply, 경로표에 [250/0] |

## 5. 되돌리는 방법

- 모듈을 꽂기 전에 반드시 저장한다. 꽂은 뒤 설정이 비면 저장한 설정으로 부팅된다
- 경로를 잘못 넣었으면 같은 줄 앞에 `no` 를 붙여 지운다
- 장애 시험 뒤에는 반드시 `no shutdown` 으로 주 회선을 살린다
